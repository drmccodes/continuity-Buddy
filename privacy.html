Privacy and governance

This is software, not NHS approval. Do not import actual patient data without your organisation's information governance and clinical safety authorisation.

What is processed?

CSV files containing the internal EMIS patient identifier only, the selected GP and search category, and your local review decisions. EMIS identifiers are personal data when linkable to patient records. The application rejects extra CSV columns, unexpected headers and non-numeric values, but cannot reliably distinguish a deliberately mislabelled numeric NHS number from an internal EMIS number. The importing clinician must verify the source.

Where does processing happen?

In your browser's volatile memory on the device you are using. Imported CSV contents, recommendations and exports are not sent to this site's servers. The app has no patient-data API, database, analytics, remote AI or user account. It does not use cookies or browser storage to retain patient data.

What leaves the browser?

Ordinary HTTPS requests to load this website's code and static assets may transmit technical metadata such as your IP address, time, hostname, user agent and request path to the hosting provider and network operators. These requests do not include imported CSV data. Clicking external documentation links, if provided, would contact those websites. Never put patient identifiers in links or URLs. The provider can technically change the code served in future releases; inspect deployment trust and use organisational security controls.

How long is data retained?

The app does not intentionally persist imported patient data. The Clear all patient data function removes patient identifiers and results from application state and visible tables, invalidates imports still being read, and revokes generated object URLs when possible. Clearing cannot guarantee memory erasure by the browser or OS, purge downloads, clipboard, screenshots, browser snapshots or print spool files. Closing a tab is not a secure deletion method.

Offline operation and updates

Once installation of the application shell completes, the app can load offline using a service worker that caches only fixed public code/assets, not CSVs, patient data or reports. Updates to the service worker are not force-activated into an existing browser session. An installed version may be older than the latest website and should be closed and reopened between clinical sessions for reviewed updates. This protects against accidental live replacement, but is not protection against compromise of a future downloaded release, the hosting provider, the browser, device or extensions.

Reports

Only explicitly requested reports are generated, in this browser. Exported CSV files and printouts contain confidential patient identifiers and must be stored and disposed of under your practice's approved information governance rules. Exports are not automatically saved by the application, but your browser will save them locally when you click Export.

Practice responsibilities

The practice determines purpose, legal basis, access, retention, patient transparency, permitted processing and whether its use is proportionate. It should assess the need for a DPIA, complete local security and clinical-safety assurance, and document lawful basis and any applicable Article 9 condition. No automatic usual-GP changes occur. All proposals require clinical review, patient preference checks and local approval.

Developer role

The developer supplies code but does not receive the uploaded patient data in the intended architecture. This alone does not conclusively determine legal controller/processor roles: the actual deployed relationships and data flows must be assessed. The provider may process ordinary technical website-access metadata.

Clinical-safety standards

DCB0129 (manufacturer) and DCB0160 (deploying organisation) are relevant to assess for a tool that influences patient allocation and continuity decisions. A risk assessment, clinical safety case, hazard log and local sign-off should be established as appropriate. The tool is not NHS-endorsed or GDPR-certified.
